## 2. The `session_candles` dimension

`session_candle_check(open_times, step_seconds, config)` is pure and deterministic. It runs over
the candles of the selected window (the same window the other dimensions judge):

| Case | Classification | Effect |
|---|---|---|
| The candle interval lies **entirely** inside configured closure(s) | `unexpected_candle_in_closure` | **fail**, so the window is **rejected** |
| The interval overlaps a closure but contains some scheduled open time | Boundary overlap, in `evidence.boundary_overlaps` | **information only**: no reason, status stays `pass` |
| No overlap | — | pass, nothing recorded |

**Evidence per candle:**
- open time `t`;
- `interval` [open, close);
- every applicable `closures` entry (`kind` weekly or holiday, `start`, `end`);
- `closed_parts` and `open_parts`, the exact sub-intervals inside and outside the closures.

**Dimension evidence:** `timeframe`, `session_config`, `candles_checked` and `boundary_overlaps`.
The failure reason carries `timeframe` and every unexpected candle.

**Raw data untouched:** candles are never removed or altered. The window's candle list stays
exactly as received, and the result is reported instead (tested).

## 3. Interval semantics

- **Candle:** the half-open interval `[open, open + timeframe)`. Timezone-aware UTC throughout.
- **Closures:** taken from T3's own `closures_overlapping(start, end, config)`:
  - each closure is `[close, reopen)`, built from America/New_York wall times per date by T3, so
    US DST is handled by `zoneinfo` and no UTC offset is hard-coded;
  - only *configured* closures (weekly; 25 Dec and 1 Jan) count. Unconfigured or unknown closures
    are never treated as known, and T3's classifications are untouched.
- **Union:** the overlapping closures are clipped to the candle and merged (a Monday holiday joins
  the weekend closure). A candle is unexpected only if that union covers its whole interval.
- **Reopen tolerance isn't closed time.** T3's 20-minute tolerance (`reopen_deadline`) lets a
  first candle be *missing*. Candles inside it are legitimate, so it plays no part here (tested).
- **Open time alone doesn't decide.** A candle whose open time is inside a closure but whose
  interval reaches past the reopen is valid (tested).

## Remaining limitations

- **Configured closures only.** An unconfigured closure (another holiday, an early close) won't
  flag its candles. That's by design, since only configured closures are known closures, but it
  means `session_candles` is only as complete as the provisional T0-based configuration.
- **Only the selected window is checked**, consistent with the other dimensions.
- **Not verified live:** T1/T2 live verification against the Exness terminal is still outstanding
  and needs your permission to restart the backend.
